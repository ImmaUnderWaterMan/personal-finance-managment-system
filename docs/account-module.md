# Модуль финансовых счетов

`PersonalFinance.AccountModule` реализует создание, получение списка и отдельного счета, переименование, архивирование и проверку доступности счета.

DTO и интерфейсы находятся в `PersonalFinance.Contracts.Accounts`. Другим модулям достаточно `IAccountValidationService`; они не должны читать внутреннее хранилище счетов.

Правила:

- название обрезается по краям и содержит от 1 до 100 символов;
- начальный остаток может быть отрицательным, имеет максимум два знака после запятой и соответствует PostgreSQL `numeric(18,2)`;
- начальный остаток после создания не изменяется; текущий баланс будет рассчитываться по финансовым операциям;
- чужой и отсутствующий счет возвращают одинаковый код `ACCOUNT_NOT_FOUND`;
- архивный счет остается доступным в истории, но проверка возвращает `ACCOUNT_ARCHIVED`;
- повторное архивирование безопасно;
- счета могут иметь одинаковые названия: их идентичность определяется `Id`;
- вызывающий сервер передает `userId` из авторизованного контекста, а не из тела запроса клиента.

`InMemoryAccountRepository` предназначен для разработки и тестов. При перезапуске данные теряются. PostgreSQL-реализация `IAccountRepository`, API и подключение WPF будут добавлены отдельно. Проверка счета перед будущей записью операции сама по себе не гарантирует защиту от одновременного архивирования: это необходимо обеспечить при реализации транзакционной границы.

Проверка:

```powershell
dotnet build
dotnet test tests/PersonalFinance.UnitTests
```

Локальная сборка возможна через существующее решение. Файлы `.slnx` исключены из Git; после клонирования библиотеки можно собирать непосредственно по их `.csproj`.
