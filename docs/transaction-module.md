# Модуль финансовых операций

`PersonalFinance.TransactionModule` ведет категории, регистрирует доходы и расходы, возвращает историю и сумму расходов по категории. Общие контракты размещены в `PersonalFinance.Contracts.Transactions`.

`TransactionService` использует `IAccountValidationService` из модуля счетов. Прямой зависимости от реализации `AccountModule` нет. Владелец счета проверяется перед сохранением новой операции; архивный или чужой счет отклоняется. Проверка и будущая запись в PostgreSQL потребуют общей транзакционной границы для защиты от одновременного архивирования.

Правила:

- категория принадлежит пользователю, имеет название от 1 до 100 символов и тип `Income` либо `Expense`;
- тип категории должен соответствовать типу операции;
- сумма положительна и соответствует PostgreSQL `numeric(18,2)`, лишние знаки не округляются автоматически;
- комментарий необязателен и ограничен 150 символами;
- операция после регистрации не редактируется и не удаляется;
- финансовая дата передается как `DateOnly`; диапазон истории включает начало и исключает конец;
- сервис принимает финансовую дату как указанную пользователем, без преобразования часового пояса;
- ошибка сводки возвращает `Total = null`, отсутствие расходов — успешный ноль;
- `userId` передает сервер из авторизованной учетной записи.

Повторная регистрация использует пару `(UserId, RequestId)`. Одинаковый запрос возвращает прежнюю операцию, измененные данные с тем же ключом вызывают `REQUEST_CONFLICT`. Сравниваются все поля запроса, включая комментарий. Повтор уже зарегистрированной операции работает и после архивирования счета. Метод репозитория `AddOrGetAsync` обязан атомарно обеспечить уникальность ключа; реализация в памяти использует блокировку.

Хранилище пока находится в памяти. PostgreSQL, API и подключение WPF добавляются отдельно. `IExpenseQueryService` подготовлен для будущего `BudgetModule`.

Проверки:

```powershell
dotnet test tests/PersonalFinance.UnitTests/PersonalFinance.UnitTests.csproj
dotnet test tests/PersonalFinance.IntegrationTests/PersonalFinance.IntegrationTests.csproj
```

Интеграционные тесты проверяют взаимодействие двух реальных модулей через контракт; это еще не проверки HTTP API или PostgreSQL.
